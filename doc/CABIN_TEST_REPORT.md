以下状态只适用于本次 `dtx` 移植；不能把 `gsx` 的历史通过记录当作 `dtx` 已验证。

隔离测试使用独立临时 socket 和 SHM，没有接入正在运行的设备 Broker。
程序构建成功只证明编译通过，不证明当前机器固件与产物可直接混用。

本分支保留 `dtx` 的原有传输和两类既有视觉会话（首层、光路），不引入 `gsx`
的测高流水线。UPDF 包头仍是 8 字节，不含 `gsx` 新版本的 `fd_count` 字段；
部署时须确认机器的 Broker、Camera、Visual 等使用兼容传输版本。

`dtx` 的既有 SHM 环仍按每个槽位分别递增 `seq`，消费者却用单个 `last_seq_`
跨槽挑选帧。负载较高、多个槽位同时在用时，帧顺序、丢帧或取帧停顿风险尚未验证；
本次隔离测试使用低负载模拟 Camera，不能据此声称覆盖真实多槽压力场景。
此问题来自原有取流层，本次没有修改公共环实现或给舱检另造本地序号；
新模块无新帧时按超时返回 `Unknown`，不能据此推断门或基板状态。
SOC 需在本机生产 Camera/SHM 路径补充持续取流与负载验收。

## 现场录像抽帧复核（本次 dtx 已重跑）

本次用 `dtx` 新构建的 `cabin_frame_check`，将原项目中四张 PNG 转为紧凑 NV12，
调用 C++ 单帧函数；两份候选标定均显式加载。结果与原 `gsx` 抽帧结果一致，已知失败仍存在。
这不是设备实时流测试，也不代替生产 DMA/NV12 验收。

| 录像与帧 | 基板输出 | 门输出 | 结论 |
|---|---|---|---|
| 23:24:27 录像，190 s，无板有码 | 1 / `QrFound`，分数 1.000 | 2 / `Clear` | 符合样本标签 |
| 23:32:18 录像，150 s，有板稳态 | 2 / `QrAbsentSceneOk`，分数 0.221 | 2 / `Clear` | 符合样本标签 |
| 第一段录像，100 s，六灯开、近黑 | 0 / `Unknown` | 1 / `Occluded`，Y 均值 16.128 | 黑画面不被当作有板 |
| 第一段录像，83.5 s，局部门遮挡 | **2 / `QrAbsentSceneOk`，分数 0.146** | 2 / `Clear` | **已知失败：不能证明基板存在** |

最后一行保留为失败，不纳入“现场全部通过”的结论。此模块不提供关门到位反馈；
SOC 必须在机构停稳且工作区域可见后才请求基板检测。粉尘／工具挡码、相机偏移等
负样本还需要实机验收，不能仅靠软件测试或这四张抽帧批准量产。
