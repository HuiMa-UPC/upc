本分支用于 SOC 与视觉联调，不是生产发布。源代码基础为同事 `gsx/860e4a1`，另包含本地内置参数；没有合入 `C:\Users\A\upc` 的未完成修改。既有 gsx 功能仍在，不声称这是删掉其余功能的极简固件。

- 分支：`test/plate-fullflow-20260924`
- 独立目录：`C:\Users\A\upc-plate-test`

- 本轮不部署测试机，不创建云端升级任务，不操作门、Z 或打印。

## 1. 包内有什么

同一版 Broker、UI、Glavo、Camera、Media、Xfer、Visual、MQTT，加启动脚本与清单。Visual 内置门参数、基板区域和 5 张码模板，普通操作人员不需要管理 JSON／PNG。已有工程覆盖仍优先，坏覆盖返回 Unknown；工程人员需注意旧配置可能影响对比结果。

该包只适用于匹配 gsx 的传输协议与应用 A/B 升级机制，不能安装到旧 dtx 固件。安装和备份／回退由 SOC 核对目标机版本后按既有流程执行；不要只替换某个不兼容的二进制。

## 2. 实机测试前提

这些是现场操作人员与 SOC 的验收要求，本轮尚未执行。

1. 在隔离的测试设备上验收，确认机构运动范围、急停和既有安全互锁正常。不要为了通过检测开启 Skip Outer Door、Env Sim 或绕过其他安全检查。
2. 确认 About 显示 `V4.2.0.2-plate-test1`，八个进程来自同一包；保留可恢复的原程序版本。
3. 六路灯、相机实际图像、码布局与检测位置满足条件。参数来自 1080×1280、Z=-20 的候选录像；机构准备归 SOC，不由算法判断 Z。
4. Debug → Other → Print Gates 中，`Plate Present` 默认 Off；现场测试时由 SOC 开启。是否同时开启 `Inner Door Occl` 按该次传感器融合用例决定。其他检查保持测试机原有安全要求，不能为了“只测基板”随意关闭。
5. **这是起印完整流程，不是仅返回识别结果的诊断按钮。** 发起起印会执行 SOC 的 Z／门动作；基板通过后会继续后续检查，满足条件时会正式打印。必须使用获准的测试作业并具备打印条件，不能靠操作人员赶在出光前按停止来保证安全。
6. `Plate Height Adj` 独立默认 Off，开启 `Plate Present` 不会自动开启测高。检测位 -20 mm 不等于已经建立可打印工作面；实际打印的工作面、测高 LUT 和相应开关必须由 SOC／工艺确认，不能仅凭基板通过就认定打印条件已满足。
7. **外门提示框的 Cancel 会跳过外门检查并继续，不是终止打印。** 下文“Cancel 阻断”仅指 `Place the build plate` 放板提示框。取消整个测试应使用真正的打印终止流程，禁止用外门 Cancel 绕过安全条件。

## 3. 当前代码流程与验收点

经批准发起测试起印后，SOC 准备 Z、检查外门、完成内门套件，再请求基板检测。UI 显示 `Checking build plate...`。

- **无板、有约定码**：Visual 回复 `QrFound` 后结束本轮；SOC 执行内门／外门打开流程，弹出 `Place the build plate`。放板期间没有新的基板请求，也不得把门遮挡造成的无码直接当成有板。
- **放板与确认**：等待门动作完成后放板、关外门，再点 `Confirm`。SOC 重新检查外门；外门仍开或未知则再次弹窗，不通过。
- **复检**：外门条件满足后再次处理内门，待流程允许时发新的基板请求。仍有码则再次提示放板；可用画面无码则通过，进入后续起印流程。
- **取消／终止**：`Cancel` 应阻断起印；终止应取消等待。之后的迟到视觉回复不能重启本次流程。
- **Unknown／超时**：不当作有板，不继续起印。检查相机、灯、遮挡、所选参数和通信日志。

内门视觉当前采用 SOC 的决策点 `Snapshot` 与传感器融合。Visual 的 `WaitOpen` 能力保留，但此完整流程没有在门运动中自动开启持续监听；这与用户早期提出的“开门过程中持续等黑”不是同一种调用方式，现场验收须明确此差别。

## 4. 留存证据

每轮记录版本、开关、灯状态、场景、session/request ID、Visual 结果、SOC 后续动作及是否还有检测请求。可只读查看 `/var/log/topic/topic_print_flow.log` 与 `/var/log/topic/topic_visual_firstlayer.log` 中的 `cabin`、`plate`、`occl` 日志；不要在设备真实 Broker 上再运行一个 APP_GLAVO／APP_VISUAL 测试客户端。

至少覆盖：初次有板、无板后放板、确认后仍无板、外门未关、Cancel、终止、无帧超时、黑画面、坏工程覆盖、门／基板交替多轮、两开关关闭时原流程回归。

已知边界：历史局部门遮挡帧会被判为无码／有板；粉尘、工具和安装偏差也需要实机负样本验收。稳定连帧不是机械关到位证明，不能宣称该风险已解决。

## 5. 测完后的清理

不要现在删除分支。先完成实机验收，将需要保留的提交合入维护分支或另存补丁，再确认临时目录没有未保存改动、设备已退出测试版本。之后才删除临时工作树和本地／远程临时分支；这些清理不会自动回退机器上的程序，设备回退必须单独完成。
