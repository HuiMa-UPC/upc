## 1. 功能目标

Confirm Print 之后、激光出光之前，用红光常亮把振镜依次打到 **中心 + 四角** 五个点。每个点由视觉在 **3 秒** 内确认画面里能看到红点：

- 识别到 → 立即切下一点。
- 超时未识别到 → 整轮失败：禁止本次打印，跳终止结果页，消息中心挂一条 Critical 卡。不弹 toast。
- 五点都过 → 切激光模式，继续原来的起印流程（含首层检测，如果开着）。

优先级高于首层检测。调试页 **Skip Optical Path Chk**：**默认关=要做光路**；按下后跳过。

五个点的毫米坐标（未经校准变换，编码时走 `cal.csv`）与调试页 `Galvo Point Test` 完全相同：

| index | 位置 | X mm | Y mm |
|------|------|------|------|
| 0 | 中心 | 0 | 0 |
| 1 | 右上 | +30 | +30 |
| 2 | 右下 | +30 | -30 |
| 3 | 左下 | -30 | -30 |
| 4 | 左上 | -30 | +30 |

改坐标前，先用调试页那个按钮看五个点是否都还在相机视野里。

## 2. 图像从哪来（不是推流）

Visual 侧是 **零拷贝 DMA + SHM 元数据环的 pull 模型**，和首层检测共用同一路 Camera visual peer：

1. Glavo 发 `GLAVO_Visual_OpticalPath_Session_Start_Ntf`。
2. Visual 向 Camera 要流（若首层会话已经在取流则复用，不拆不重拉）。
3. Camera 经 `SCM_RIGHTS` 把 dma-buf fd 交给 Visual；SHM 环只传槽位状态和 `buffer_idx`。
4. Visual 后台线程 `acquire_latest_frame()`（latest-wins，中间 READY 槽直接丢）→ `copy_nv12_tight()` 得到 **紧凑 NV12**。
5. 光路检测 **不用** `recent_snapshots_`（那条 deque 按 stride=3 抽帧，是给首层时序中值用的）。红点轮询走 `copy_latest_snapshot()`，每帧都是当前最新图。

紧凑 NV12 布局：

```text
nv12[0 .. width*height)                     Y 平面
nv12[width*height .. width*height*3/2)      UV 交错，半分辨率
bytes == width * height * 3 / 2             无 stride padding
```

红点判定必须用色度，所以 `detect_nv12()` 传的是整帧，不是只给 Y。

## 3. 你们要写的函数

`RedDotDetector::Impl::detect()`（`red_dot_detector.cpp`）。当前是 fail-closed 桩：恒返回 `found=false`、`reason="not_implemented"`。把桩替换掉即可，**不必改** VisualService / Glavo / UI。

```cpp
RedDotDetection detect_nv12(const uint8_t* nv12, std::size_t bytes,
                            uint32_t width, uint32_t height,
                            uint32_t frame_seq, const RedDotHint& hint);
```

| 入参 | 含义 |
|------|------|
| `nv12` / `bytes` / `width` / `height` | 紧凑 NV12，见上节 |
| `frame_seq` | 相机帧序号，只用于日志对齐 |
| `hint.expect_x_mm` / `expect_y_mm` | 本点振镜坐标（mm），可做 ROI 预测 |
| `hint.point_index` / `point_total` | 0=中心 … 4=左上；总数当前为 5 |

| 出参 | 含义 |
|------|------|
| `found` | **唯一放行条件**。true=本帧确认看到红点 |
| `center_x` / `center_y` | 像素中心（左上原点）；失败无意义 |
| `area_px` | 连通域面积，便于日志判断是否把噪点当红点 |
| `confidence` | 0.0~1.0，跨进程按 ×256 传到 Glavo，只进日志 |
| `total_ms` | 本帧耗时 |
| `reason` / `error` | 失败归因 / 算法自身出错 |

硬约束：

1. **fail-closed**：入参非法、模型缺失、内部异常一律 `found=false`，绝不返回 true。
2. **单帧判定**：不要跨帧累计“大概是”。窗口内多帧轮询由 VisualService 做。
3. **要快**：单帧目标 <30ms。轮询周期约 33ms，3 秒窗口大约能看 ~90 帧。
4. 会话开始会调 `reset_session()`，跨点缓存在这里清。

### 实现提示

- 红点在 YUV 里：V 显著高于 128，Y 也偏高。先在 UV 平面做色度阈值再取连通域，通常比转 BGR 再走 HSV 快。
- 相机自动曝光会被亮红点拉低整体亮度，**不要用全局亮度做前置否决**。
- `hint` 的毫米坐标还没有像素标定。没有标定表时可以先全图搜；有了标定再收 ROI。
- 接入后若第 0 点仍 3 秒失败，按这个顺序排：
  1. 取流到底起来没有 —— 日志里应有 `camera stream`/`take dma fds`，没有就说明 `on_stream_start_rsp`
     把回执丢了（历史上就踩过：那里的会话判据必须是 `any_session_active_locked()`，
     光路检测单独激活时首层会话是关着的）。
     `reason=no_frame`（或 Glavo `fail_code=1`）：等帧阶段一直没有 NV12 快照，检测器没跑。
     查 `visual stream attach failed`（回执没接上，会话结束仍会 Stop）和 Camera 的
     `slot unread, released for other peers`（视觉槽没人读，不能再把预览钉死）。
     有帧但找不到红点时 Visual 打 `no_red_pixels` / `area_too_small`，Glavo 记 `not_found`。
     旧日志里的 `reason=timeout` 且同时 `preview stalled` 也是同一类空快照问题。
  2. 红点在不在画面里 —— 调试页 `Galvo Point Test` 目视确认。
  3. 算法有没有被调到 —— 查 `optical path rsp` / `red dot detect` 日志。

## 4. IPC 契约（Glavo ↔ Visual ↔ UI）

定义：`common/upc_contract.hpp`。可靠投递（`is_ipc_reliable_msg_type`）。

### 会话

| MsgType | 方向 | Payload |
|---------|------|---------|
| `GLAVO_Visual_OpticalPath_Session_Start_Ntf` (`0x1428`) | Glavo→Visual | Empty |
| `GLAVO_Visual_OpticalPath_Session_Stop_Ntf` | Glavo→Visual | Empty |

Start/Stop 与首层会话独立计数。Visual **两类会话共用一路流**：任一还在，Stop 其中一类不得拆流。

### 单点识别

`GLAVO_Visual_OpticalPath_Point_Check_Req` → `VisualOpticalPathCheckReqPayload`

| 字段 | 含义 |
|------|------|
| `point_index` / `point_total` | 当前点 / 总数 |
| `expect_x_mm_x10` / `expect_y_mm_x10` | 期望振镜坐标 ×10（0.1mm） |
| `timeout_ms` | 判定窗口，当前 3000 |
| `session_id` | 本轮世代号，**回包必须回显** |

`APP_Visual_OpticalPath_Point_Check_Rsp` → `VisualOpticalPathCheckRspPayload`

| 字段 | 含义 |
|------|------|
| `result` | 1=识别到，0=未识别到 |
| `point_index` / `session_id` | 回显，用于丢弃迟到包 |
| `reserved[0]` | `result=0` 时：`1`=整段无快照（`no_frame`），`0`=有帧未找到 |
| `detected_x_px` / `detected_y_px` | 像素中心；失败填 -1 |
| `confidence_q8` | 置信度 ×256；失败为 0 |

Glavo 用 `session_id + point_index` 配对。上一点的迟到回包会被丢掉，避免把“上一点还亮着”误判成本点通过。

Visual 先等第一帧（最多约 8s，空快照不算「没找到」；期间可 nudge 起流），再在 `timeout_ms` 内反复取最新帧调 `detect_nv12()`。命中即回 `result=1`；无帧回 `result=0` 且 `reserved[0]=1`；有帧未找到回 `result=0` 且 `reserved[0]=0`。轮询跑在独立线程上，不堵 Visual 主循环的 `tick()`。被 abort 时不回包。

Glavo 兜底等待为 `8s + timeout_ms + 700ms`：覆盖等帧 + 认红点 + IPC。Visual 进程挂了也按失败处理。

### UI

- `APP_OpticalPath_Progress_Ntf`：逐点进度。`state`：0=移动中 1=该点通过 2=该点失败 3=整轮完成（徽标回到 PRINTING）。
- `APP_Print_Start_Rejected_Ntf`：失败时让 UI 跳终止结果页。
- 调试开关：`UI_Debug_OpticalPath_Check_{Set,Get}_Ntf` / `GLAVO_Debug_OpticalPath_Check_Ntf`，默认关。

设备事件（消息中心，失败不弹 toast）：

| 码 | 等级 |
|----|------|
| `OpticalPathCheckStarted` (31) | Info |
| `OpticalPathCheckPassed` (32) | Info |
| `OpticalPathCheckFail` (33) | Critical |

## 5. 时序（单点）

```text
Glavo 检测线程                         Visual 取点线程
  发 Session_Start  ─────────────────►  请求 Camera 起流
  apply_red_always (TCP Red=3)           dma-buf 分配 → 回执 → mmap
  睡 1500ms 取流预热                     → 拉起取帧线程 → 第一帧
  ┌── 每点循环 ──────────────────────────────────────────────┐
  │ 编码并下发 11B 运动子包
  │ 睡 250ms settle（TCP+MCU+曝光）
  │ 发 Point_Check_Req ──────────────►  循环：
  │                                       copy_latest_snapshot()
  │                                       detect_nv12()
  │                                       found? 立即 Rsp result=1
  │                                       否则 ~33ms 后再取
  │ wait(timeout+grace) ◄──────────────  窗口耗尽则 Rsp result=0
  │ 通过 → 下一点；失败 → 跳出
  └──────────────────────────────────────────────────────────┘
  发 Session_Stop   ─────────────────►  两类会话都停才拆流
  通过：切激光，继续 open/parse/首层
  失败：红光安全态 + Critical 报警 + 终止页
```

两处等待各有各的理由，都不能省：

- **等第一帧（单点内，最多约 8s）**：Session_Start 只是请求起流，Visual 还要走完
  申请 → dma-buf → 回执 → mmap → 取帧线程 → 第一帧。这一段空快照不算「没找到红点」；
  整段仍无帧才记 `no_frame`。Glavo 不再用固定 1.5s 盲等替相机买单。
- **settle 250ms**（每点一次，`kPointSettle`）：运动包刚发出时前几帧画面还停在上一个点，
  不留这段会把四个角连锁误判成通过。
- **认红点 `timeout_ms`（当前 3000）**：只在已有帧之后开始计时。

## 6. 联调步骤

1. 调试页 Other → `Galvo Point Test`：确认五个红点都在相机画面内、停留稳定。
2. 默认会做光路；要跳过就按 `Skip Optical Path Chk`（`1st Layer Visual` 可先关，减少干扰）。
3. 算法仍是桩时：Confirm Print → 进打印页 → 徽标 `OPTICAL PATH CHECK` `1/5` → 有帧后约 3.7 秒内（或等帧超时约 8s）跳终止页，消息中心 Critical「Optical path abnormal」。用来验证阻断链路。
4. 接入算法后：五点依次 `n/5`，通过后徽标回到 `PRINTING...`，进度条从 0 开始走。
5. 检测过程中终止钮可用，暂停钮是灰的。
6. 失败后 prepare 缓存（本地副本、行数）保留，再打同一文件不会重拷。

日志关键字：`optical path`（Glavo） / `red dot detect`（Visual） / `optical path session`。
