# 视觉协作：内门遮挡与基板在位

本文给视觉、Glavo、UI 三端对齐。算法未接入前，调试页相关开关 **默认关**，关着时起印与内门套件 **保持现逻辑**。

对照已落地的同类文档：[视觉协作-光路检测.md](视觉协作-光路检测.md)、[FIRST_LAYER_VISUAL_DEV_GUIDE.md](FIRST_LAYER_VISUAL_DEV_GUIDE.md)、[视觉协作-基板测高.md](视觉协作-基板测高.md)。取流模型与光路相同（Camera DMA + SHM，Visual pull 紧凑 NV12），不要用 UI 预览当算法输入。

**本文状态：** 舱检 IPC / Visual 算法以 [CABIN_IPC_INTEGRATION.md](CABIN_IPC_INTEGRATION.md) 与 `upc_contract.hpp` 的 `VisualCabinSessionPayload` / `VisualCabinCheckReqPayload` / `VisualCabinCheckRspPayload`（MsgType `0x1720`–`0x1725`）为准——**不要沿用下文旧 Empty / Inspect 载荷草稿**。Glavo↔UI 侧：挡门决策点融合、起印 Z→−20±1、读码闸门、无板弹窗、调试两开关（默认关）已按本文业务口径接线；算法缺配置时 fail-closed 回 Unknown。

**挡门视觉的触发口径（已拍板）：** 不限打印。凡走 `run_inner_door_motion_kit` 的入口——**Manual Inner Door、调试页开/关、起印关内门、外门开→关边沿补关**——只要挡门开关开，在 **读全开开关并决定是否跳过/开跑套件** 时同步发一次 Occlusion Req，等到结果后与 bit1 做 **或**。套件一旦开跑（降 Z、门电机、等 2 s、回 Z），半开/运动中途 **不再问视觉**。不在 MCU 周期 `EnvSnapshot` 上报里刷视觉。读码（基板在位）仍只挂在起印 Prep（及无板弹窗再检），不挂到每次 Manual 开关门上。

## 1. 要解决什么

| 问题 | 做法 |
|------|------|
| 内门全开接近开关（MCU 1ST bit1 / `UP_SWPD`）易坏 | **全开** = 开关为 1 **或** 视觉判定镜头被内门挡住（近黑）。只增强「全开」，不提供关到位 |
| 空平台起印 | 平台上印有二维码：**稳定认出约定码 = 无基板**；画面正常且无该码 = 有基板。无板则弹窗，用户放板并关外门后再检 |
| 内门动作刮到基板 | 视觉开且判定舱内有板时，开门/关门前把 Z **绝对到位 −20 mm**；无板则不动 Z |
| 打印工作面 | 基板视觉开时，**一进打印 Z 先到 −20 mm**，之后高度只交给测高，不再抬回进印前的 Z |

视觉 **只看图、回三种结果**（挡门 / 读码 / 未知）。或逻辑、弹窗、动轴、融合亮钮都在 Glavo。

## 2. 现逻辑约束（开关关闭时必须仍成立）

这些是当前代码事实，视觉关时不得改语义。

### 2.1 内门传感器

- `EnvSnapshot.inner_door_open`：1ST **bit1 只表示全开**（1=全开，0=非全开：半开/暂关/全关都可能）。**没有关到位。**
- 开套件：仅静止全开才跳过；关套件：仅静止非全开才跳过；未知则开/关都跑。
- **上电不自动关内门。**
- Manual / 调试 / 起印关内门 / 外门开→关边沿 **同一套件**（`run_inner_door_motion_kit`）。
- 现套件：记当前 Z → `AXIS_INC −20 mm` → 门动作 → 等 2 s → **回到降前 Z**；`wait_z_settled` 公差 1 mm、超时 8 s。
- 套件 busy：`GLAVO_Debug_Inner_Door_Busy_Ntf`，Manual/调试禁钮；连点入队去重。
- 外门关边沿时若套件忙 / 打印发送中 / 预检中：记下，事后补关。

### 2.2 起印环境检查（`UI_Print_Start_Req` 之后）

`print_running_` 在检测一开始就置位。本趟实际会跑的步才进 `APP_Print_Prep_Progress_Ntf`（`PrintPrepStep` **只准末尾追加**）。

当前顺序：

```text
外门闸门 → 关内门套件 → 光路 → 测高 → open/parse
  → 开扫后：氧门 → 首层视觉 → Ready
```

| 步 | 现行为 |
|----|--------|
| 外门 | 已关则跳过。未关/未知：`GLAVO_Outer_Door_Confirm_Req`，UI Confirm 再读门、仍开再弹；Cancel=`skip=1` 不检门仍去关内门。调试 **Skip Outer Door** 跳过外门 **和** 关内门 |
| 关内门 | 静止 bit1=0 跳过且不占 Prepare 步 |
| 光路 / 测高 | 各自调试开关，默认关；光路失败阻断；测高无 LUT 或失败阻断（`PlateHeightFail`） |
| 氧 / 首层 | 开扫之后仍算 Prepare；Skip O2 / 关首层则不计 |

失败走 `abort_print_start()`，SOC 舱灯打满。Prepare 终止可打断外门等待与关内门。

无板弹窗的 **等待 / Confirm 再检 / 仍不满足再发 Req / 终止打断** 与外门闸门同一套挂起，**文案与再检条件不同**（见 §5）。不要复用「只关外门」那句英文。

### 2.3 舱灯与取流

- 舱灯是 SOC 六路 `lgt1l`…`lgt3r`（`DebugSocLedStatePayload.mask`，bit0=`Lgt1L` … bit5=`Lgt3R`），**不是** MCU Device/Light。上电 `set_all_cabin_leds(true)` 六路全开。
- `set_cabin_light(false)` 出现在光路/测高；与挡门、读码 **禁止并发**。
- Visual 空闲不取流。起流条件是 `any_session_active_locked()`（今日：首层 **或** 光路 **或** 测高）。新舱检会话必须挂进该函数的 **全部三处**（`send_stream_start_req` / `on_stream_start_rsp` / `release_stream_if_idle`），否则会像早期光路一样开了会话不起流。见 `app/visual/VISUAL.md`。
- 监控页预览在 UI 进程，**不能**代替 Visual 的 NV12。

### 2.4 Z 坐标

- MCU Z Home 停在约 **1.00 mm**。下降为负。Manual：`Top`=1 mm，`Bottom`=**−10 mm**，绝对到位走 Axis_Jog `dir=0`。
- 本需求的安全位是 **绝对 −20 mm**（不是再相对减 20）。偏离 −20±1 时 **升或降** 都绝对到位（偏低也抬回）。
- 测高仍会按 LUT 调工作面；基板视觉开时，进印后的「原 Z」作废，工作面以测高为准。

## 3. 调试开关（仅本次 Glavo 进程，默认关）

| 开关 | 关（默认） | 开 |
|------|------------|----|
| **内门视觉挡门** | 全开只信 bit1；套件 Z 仍相对 −20 再回 z0 | 全开 = bit1 **或** 挡门；融合结果推 UI |
| **基板在位** | 不起印读码、无放板弹窗、进印不强制 −20 | 进印先 Z→−20；关内门后读码；无板弹窗循环 |

两个开关分开。只开挡门、不开基板：融合全开仍做，套件 Z **仍走现逻辑**（相对降并回 z0），因为「有板才去 −20」依赖读码。只开基板、不开挡门：全开仍只信开关；进印仍先 −20 并读码。

## 4. 视觉开时：起印顺序

```text
launch_print_from_prepared
  ① 基板开关开：Z 绝对到位 −20 mm（|z+20|≤1 跳过；偏高降、偏低抬）
  ② 外门闸门（现逻辑；Skip Outer Door 仍跳过 ②③）
  ③ 关内门（融合全开才跑套件；Z 已在 −20 则套件不再动 Z，也不回 z0）
  ④ 六路舱灯全开 → 短等曝光（TBD）→ 舱检会话 → 读码
       有板：停会话 → 光路 → 测高（此后 Z 只由测高改）→ … → Ready
       无板或门又开了：弹窗（§5）→ Confirm 后再检外门已关 + 再读码
       unknown / 超时 / Visual 无应答：abort_print_start（阻断）
```

**读码只标定 Z=−20 mm 这一种画面。** 内门未关严时禁止把「看不见码」当成有板（挡门/过暗 → `unknown`）。

Skip Outer Door 跳过 ②③ 后若内门仍可能挡镜头：读码得到 `unknown` 则阻断，不得当成有板。

`PrintPrepStep` 落地时 **末尾追加**（建议 `PlatePresent = 7`）。UI 标题与现步一致风格（例如 Checking build plate）。执行顺序可以是 ④，枚举值不必插到 0。Z→−20 可并进该步或静默运动，不强制单独一步。

## 5. 无基板弹窗（UI 文案不同，挂起与外门确认相同）

| | 外门闸门 | 无基板 |
|--|----------|--------|
| 触发 | 外门未关或未知 | 读码 = 无板（`qr_found`） |
| 文案 | Close the outer door / 关外门继续 Prep | **放入基板并关好外门**（开门已自动；英文稿随 UI） |
| Confirm | 再读 env：仍开再弹 | **再读外门已关，并且再读码 = 有板**；任一不满足再弹 |
| Cancel | 现：`skip=1` 不检门继续关内门 | **阻断起印**（与光路失败同类回滚） |
| 终止钮 | 打断等待 | 同样打断 |

无板触发后 Glavo **先自动开内门，再发外门开门**，然后才推放板弹窗（避免模态挡住 Manual 开门）。放板挂起期间 **关外门边沿不补关内门**（放板需要内门开着）。放板后用户关外门再 Confirm；Confirm 后 Glavo 不得假设内门状态，应再走融合；若确认后内门又全开，先关内门再读码。

## 6. 全开融合（只在 Glavo 算一次）

```text
fully_open =
    (door_state_valid && bit1=1)
    OR (挡门视觉开 && occlusion == occluded)
```

| 挡门 Rsp | 含义 | 禁则 |
|----------|------|------|
| `occluded` | 灯开且画面符合挡镜头 | 可与 bit1 或 |
| `unknown` | 无帧、超时、灯关、过曝、算法未实现 | **不得**当成 occluded |
| 非挡 | 灯开且舱内可见 | 只信 bit1 |

融合结果同时用于：是否跳过开/关套件、Manual 钮亮灭。视觉关时 UI 仍只跟 `EnvSnapshot` bit1。

MQTT `telemetry` 若继续带 `inner_door_open`，视觉开时应跟融合值，避免和钮不一致。

## 7. 内门套件与 Z（视觉开）

| 场景 | Z |
|------|---|
| 打印路径，基板开关开 | 进印已到 −20；套件不再相对降、**不回 z0** |
| Manual/调试，基板开关开且读码=有板 | 开门/关前 Z 绝对 −20；结束后 **停在 −20**（与打印一致） |
| Manual/调试，读码=无板 | 不动 Z，只做门 |
| 读码 unknown | 保守：当作有干涉，去 −20 |
| 两开关都关 | 现逻辑：相对 −20 + 回 z0 |

绝对到位用与 Manual 预置相同的 Z `dir=0`，不要对已经很低的位置再 `AXIS_INC −20`。行程可能大于 20 mm，8 s settle 不够则加长并写进实现。

Z 运动前若机构上「内门关死无法降到 −20」，须先开门再降——以结构为准，软件在文档验收里用实机确认。

视觉会话期间 Inner Door **保持 busy**，超时必须 `busy=0`，避免钮锁死。

## 8. 舱灯（必须出现在每次视觉 Req 里）

检挡门、读码之前：`set_all_cabin_leds(true)`，再带 **当前 `mask`** 给 Visual（与 `GLAVO_Debug_Soc_Led_Ntf` 同源）。视觉不读 sysfs。

| mask / 画面 | 挡门 | 读码 |
|-------------|------|------|
| mask=0 或未六路全开且画面暗 | `unknown` | `unknown` |
| 六路开，近黑/挡镜头 | `occluded` | `unknown`（禁止判有板） |
| 六路开，舱内可见 | 非挡 | `qr_found` 或 `qr_absent_scene_ok` |

产品检前强制六路全开，不完全信任用户只开一路。检完灯保持开（与现 Prep 结束 `set_cabin_light(true)` 一致）；不要在光路/测高关灯窗口里做舱检。

## 9. 视觉要交付的算法

两个函数，风格对齐 `RedDotDetector`：单帧、fail-closed、非法入参不得给出「挡门」或「有板」。窗口内轮询由 VisualService 做。无帧/超时由 Service 回 `unknown`，算法不要把空缓冲当成挡门。

取流：紧凑 NV12（Y + UV，`bytes = width*height*3/2`），`copy_latest_snapshot()`，与光路相同；不用首层 `recent_snapshots_`。

### 9.1 内门挡镜头

```text
入：nv12, bytes, width, height, frame_seq, cabin_led_mask
出：occlusion = occluded | clear | unknown；可选 mean_luma 仅日志
```

TBD（实机填）：Y 均值阈值、连帧、半开只挡一块 ROI、AE 丢弃前 N 帧。不要用全局亮度否决光路红点那套经验直接套过来——挡门 **就是** 看亮度/遮挡。

### 9.2 平台二维码

```text
入：同上（可加「码在画面中的大致区域」hint）
出：qr_found | qr_absent_scene_ok | unknown
```

产品映射（仅 Glavo）：

- `qr_found` → 无基板  
- `qr_absent_scene_ok` → 有基板  
- `unknown` → 阻断或保守动 Z，**不是**有板  

TBD：码制、尺寸、贴点、是否校验 payload、Z=−20 下的像素大小、粉尘/反光。**粉盖住码会误判有板**，验收里标明；量产可考虑读码前吹粉（非本需求必做）。

刮刀 S 若会挡码，Glavo 检前把 S 停到约定位（与视觉约定后写进实现）。

## 10. 建议 IPC（落地时写入契约）

可靠投递。会话与首层/光路/测高 **独立计数、共用一路流**。

| MsgType（名） | 方向 | Payload 要点 |
|---------------|------|----------------|
| Cabin Session Start / Stop | Glavo→Visual | `VisualCabinSessionPayload`：非零 `session_id`（见 [CABIN_IPC_INTEGRATION.md](CABIN_IPC_INTEGRATION.md)） |
| InnerDoor Occlusion Req | Glavo→Visual | `VisualCabinCheckReqPayload`：`session_id`/`request_id`/`timeout_ms`/`cabin_led_mask`/`mode` |
| InnerDoor Occlusion Rsp | Visual→Glavo | `VisualCabinCheckRspPayload`：回显两级 ID；`result`：0=unknown 1=occluded 2=clear |
| Plate Present Req | Glavo→Visual | 同上（`mode` 仅 Snapshot） |
| Plate Present Rsp | Visual→Glavo | 同上；`result`：0=unknown 1=qr_found 2=qr_absent_scene_ok |

Glavo 用 `session_id`+`request_id` 丢弃迟到包。`timeout_ms + grace` 无回包视为 unknown → 阻断起印。被 abort / 匹配 Stop 不回包。

无板挂起可复用外门确认通道或并列 `GLAVO_Plate_Place_Confirm_Req` / `UI_…_Rsp`（`skip` 仅 Cancel=阻断，不复用外门 `skip=1` 继续 Prep 的语义）。

调试：`UI_Debug_*_Set/Get` + `GLAVO_Debug_*_Ntf`，仅本次运行，默认关，与光路开关同模式。

UI Prepare 步追加后，`page_user_monitor_print_prep_update` 补标题。失败：`APP_Print_Start_Rejected_Ntf` + 消息中心事件（新 `DeviceEventCode` 末尾追加）。

## 11. 时序（读码一轮）

```text
Glavo worker                         Visual
  六路灯全开
  Cabin Session_Start  ──────────►   若无其它会话：Camera 起流
  预热（建议 ≥1500ms，同光路）         mmap / 第一帧
  Occlusion 或 Plate Req ────────►   轮询 latest NV12 + detect
  wait(timeout+grace)  ◄──────────   Rsp（unknown/occluded/…）
  Session_Stop         ──────────►   四类会话都停才拆流
```

Manual 点内门若要读码/挡门：同一会话，busy 覆盖预热+窗口。

禁止与光路、测高、首层采图并行（关灯、红光斑会污染挡门与读码）。

## 12. 失败与终止

| 情况 | 行为 |
|------|------|
| 读码 unknown、Visual 挂、超时 | `abort_print_start`，舱灯全开 |
| 无板弹窗 Cancel / 打印终止 | 清等待，回滚打印态；内门保持当时姿态 |
| 挡门 unknown | 融合忽略视觉，只信 bit1；套件 Z 按 §7 保守去 −20（若基板开关开） |
| OpenCV 未编入 Visual | 现行为 `valid=0` → 必须映射 unknown |

## 13. 视觉同事接入前的采集

灯六路全开，Z=**−20 mm**，各拍 NV12（或预览录像 + 分辨率记录）：

1. 内门全关 / 半开 / 全开（挡镜头）  
2. 无板（码可见）/ 有板（码被盖住）  
3. 灯全关对照（须判 unknown）  

阈值、连帧、ROI 用这组图填 TBD。没有 Z=−20 的图不要按 1 mm 工作面估像素。

## 14. 联调（开关打开后）

1. 两开关保持关：Confirm Print，确认外门/内门套件/Z 相对降与回 z0 与现网一致。  
2. 只开挡门：接近开关人为断开、门开挡镜头 → 仍走关套件；灯全关 → 不误判全开。  
3. 开基板：进印 Z 到 −20；无板 → 放板并关门文案；Confirm 时门仍开或码仍在 → 再弹；都满足 → 光路/测高。Cancel → 终止页。  
4. Skip Outer Door + 内门开着读码 → 阻断而非有板。  
5. 日志：`cabin inspect` / `inner door occl` / `plate qr`（实现时定关键字）。

## 15. 分工

| 端 | 做 |
|----|----|
| Visual | `any_session_active` 纳入舱检；挡门/读码检测器；Req 轮询与 Rsp |
| Glavo | 开关、融合、Z 绝对 −20、Prep 插入读码、无板挂起、busy 覆盖会话 |
| UI | 调试两开关；Prepare 标题；无板弹窗文案；融合后的 Inner Door 亮灭 |
| 视觉算法 | §9 单帧函数与 §13 阈值 |

契约未合入前，算法可先在 Visual 进程内用离线 NV12 跑通检测器，接口形状按 §9 / §10。
