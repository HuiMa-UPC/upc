# 设备端凭证轮换对接手册

> 版本：v1.1（2026-09-17，confirm 老链路升版为发现式关窗）
> 定位：面向设备端（SoC / 固件团队）的凭证轮换对接说明，讲清设备端要实现的 MQTT 行为、两阶段 HTTP 调用、签名算法与异常回落
> 依据：《SNOWX IoT 设备出厂 & 云端接入技术规范 v1.8》§6.5（mqttPassword 90 天轮换、发现式关窗）、§A.2（HMAC 签名）、§5.1（激活流程签名一致）；后端实现 `iot-device-auth`：`CredentialRotationController`（两阶段接口）、`CredentialRotationServiceImpl`（业务与签名校验）、`CredentialRotationScheduleJob`（云端调度）、`GracePeriodTimeoutJob`（超时回退）、`ReplayProtector`（防重放）、`RotationRateLimiter`（限流）
> 状态边界：凭证轮换主线已实现、可联调；设备端对接本手册两阶段 HTTP + MQTT 下行指令即可，不含平台侧调度与监控。

---

## 一、对接前置

| 项 | 要求 |
|---|---|
| 下行指令传输 | MQTT，订阅 `downlink/{deviceSn}/mgmt`，QoS 1 |
| 两阶段 HTTP | HTTPS（TLS），设备直连接口 `/api/v1`（init / rotate 两步，confirm 端点已删，完成改重连命中关窗） |
| 标识符 | `deviceSn`（出厂烧录的序列号，见规范 §4.1），MQTT 认证 username = deviceSn |
| 当前生效凭据 | `mqttPassword`（激活或上次轮换时云端下发，写入 Flash 安全区） |
| 密钥 | `deviceSecret`（出厂烧录，永不出设备，仅用于计算 HMAC 证明持有） |

**两条通道分开**：凭证轮换指令走管理通道 `downlink/{deviceSn}/mgmt`，与日志采集的业务通道 `snowpod/{region}/{device_id}/cmd` 是两条独立 topic，设备端需分别订阅、互不混用。

---

## 二、整体时序

凭证轮换由**云端主动触发**，设备端被动响应，全程两步 HTTP + 一次 MQTT 重连（云端发现式关窗）：

```
云端调度（每小时扫 password_expires_at 到期设备）
   │  ① MQTT 下行 downlink/{deviceSn}/mgmt，payload {"action":"ROTATE_CREDENTIAL"}
   ▼
设备端收到指令
   │  ② POST /api/v1/rotate-credential/init      → 拿 serverNonce（5 分钟有效）
   │  ③ 本地计算 HMAC 签名（用 deviceSecret）
   │  ④ POST /api/v1/rotate-credential            → 拿新 mqttPassword（TLS 明文，仅此一次）
   ▼
设备端写新密码 → 主动断开 MQTT → 用新密码重连
   │  ⑤ 重连命中新密码   → EMQX 鉴权回调发现式关窗，轮换完成
   ▼
（任何一步失败/超时 → 继续用旧密码，等下一周期，见 §七）
```

设备端只需做：**收指令 → 两步 HTTP → 换密码重连**。状态推进与双密码共存由云端完成。

## 三、下行轮换指令

Topic：`downlink/{deviceSn}/mgmt`，QoS 1，retain = false

```json
{"action":"ROTATE_CREDENTIAL"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `action` | string | 固定 `ROTATE_CREDENTIAL`，目前该通道只有这一种指令 |

设备端收到后，若当前无进行中的轮换，立即进入两阶段 HTTP 流程。

## 四、两阶段 HTTP 调用

### 4.0 公共请求头（两步都带）

| Header | 类型 | 说明 |
|---|---|---|
| `X-Timestamp` | int64 | Unix **毫秒**时间戳，与云端时间差不超过 **±5 分钟**，超窗返回 401 |
| `X-Nonce` | string | 一次性随机串，**16 位以上 hex**，每次请求必须新生成、不可复用（云端 10 分钟去重，复用即判重放 401） |
| `Content-Type` | string | `application/json` |

### 4.1 Step 1 发起 — `POST /api/v1/rotate-credential/init`

```
Headers: X-Timestamp, X-Nonce
Body:    { "deviceSn": "...", "clientNonce": "..." }
响应:    { "serverNonce": "...", "expiresIn": 300 }
```

| 字段 | 约束 | 说明 |
|---|---|---|
| `clientNonce` | `[0-9a-f]{16,64}` 小写 hex | 设备端本次生成的随机数 |
| `serverNonce`（响应） | 32 位小写 hex | 云端挑战值，**5 分钟内必须用于 Step 2**，过期需重新 init |
| `expiresIn`（响应） | 秒 | serverNonce 有效期，固定 300 |

**注意**：`clientNonce` 要在整个轮换周期内保持不变（Step 2 回传同一个），与 `X-Nonce`（防重放头，每请求都换）是两个不同的量，别混。

### 4.2 Step 2 执行 — `POST /api/v1/rotate-credential`

```
Headers: X-Timestamp, X-Nonce
Body:    { "deviceSn": "...", "clientNonce": "...", "serverNonce": "...", "signature": "..." }
响应:    { "mqttPassword": "...", "expiresIn": 7776000 }
```

| 字段 | 约束 | 说明 |
|---|---|---|
| `clientNonce` | `[0-9a-f]{16,64}` | 与 Step 1 一致 |
| `serverNonce` | `[0-9a-f]{32}` | Step 1 拿到的挑战值 |
| `signature` | `[0-9a-f]{64}` | HMAC 签名，算法见 §五 |
| `mqttPassword`（响应） | 32 字节 Base64URL（去填充） | **明文仅经 TLS 下发这一次**，云端即弃不落库 |
| `expiresIn`（响应） | 秒 | 新密码有效期 90 天（7776000 秒） |

### 4.3 轮换完成：重连命中即关窗（无 confirm 端点）

设备端**不调用任何确认接口**。用新 mqttPassword 重连 MQTT 成功后，EMQX 鉴权回调发现式关窗（`closeWindow`），云端自动固化 new_hash、删除轮换记录、落历史，轮换完成。

若 24 小时内（grace period）未用新密码重连命中，云端超时 job 会删除轮换记录、旧 hash 原样保留，设备下周期重新走完整流程。

## 五、签名算法（HMAC-SHA256，与激活一致）

```
key       = hexToBytes( sha256(deviceSecret) 的 hex 表示 )
signData  = serverNonce + clientNonce + deviceSn   (三个字符串直接拼接，无分隔符)
signature = HMAC-SHA256(key, signData) → 小写 hex (64 字符)
```

三个坑（规范 §A.2 反复强调，错了验签永不过）：

1. **key 是 raw 32 字节**：`sha256(deviceSecret)` 的 hex 串要先 `hexToBytes` 解回 32 字节，不能用 hex 字符串的 UTF-8 字节直接当 key，也不能拿 deviceSecret 原始明文当 key。
2. **signData 纯拼接**：`serverNonce` + `clientNonce` + `deviceSn` 直接首尾相接，中间不加空格、不加冒号、不加换行。
3. **输出小写 hex**：HMAC 结果转 64 字符小写十六进制，不是 Base64。

验签示例（伪码）：

```python
key       = bytes.fromhex(sha256hex(deviceSecret))   # 32 字节
sign_data = (serverNonce + clientNonce + deviceSn).encode("utf-8")
sig       = hmac.new(key, sign_data, hashlib.sha256).hexdigest()   # 64 小写 hex
```

## 六、新密码落地与 MQTT 重连

1. 收到 `mqttPassword` 后，**先写入 Flash 安全区**（覆盖旧密码前，旧密码仍在云端有效，见下方双密码共存）。
2. 主动断开 MQTT，用新密码重连。
3. **重连命中新密码即云端关窗**；若重连失败，走失败路径（继续用旧密码，见 §七）。
4. **双密码共存**：rotate 成功后、关窗前（grace 24 小时内），云端 EMQX 认证**新旧两个密码都接受**。所以设备端写新密码、重连稍微慢一点，也不会被旧密码立刻踢下线。关窗后云端固化新 hash、删除旧 hash，新密码唯一生效。

## 七、异常与回落（回退优先，不锁设备）

消费级原则：**任何失败都不把设备锁进「必须恢复出厂 / 人工重激活」的终态**。

| 场景 | 设备端行为 |
|---|---|
| 离线没收到指令 | 无需处理；下次上线云端调度 job 检测到期会重新下发 |
| Step 1 / 2 任一返回 401 / 失败 | 继续用旧密码跑业务，本轮放弃，等下一周期云端重新发起 |
| serverNonce 过期（超 5 分钟） | 重新走 Step 1 init 拿新 nonce |
| Step 2 后重连失败 | 未命中新密码不关窗，继续用旧密码；grace 超时云端自动回退旧密码 |
| 重连被 deny（持新密码但 grace 已回退） | 回退旧密码重连（旧 hash 仍在、可正常续连），无需 Reset |
| 收到 429（限流） | 不要立即风暴重试，退避等待，下周期再说 |

云端侧对等的回退语义（设备端可据此理解）：
- 任一步失败/超时 → 云端保留 `device_credentials` 旧 hash 原样，设备旧密码照常可用。
- grace 24 小时超时未关窗 → 删除轮换记录、旧 hash 不动，设备回落旧密码，下周期重新 init+rotate 生成**全新**密码再试。
- recovery（持新密码、grace 已回退）：超时 job 已删 rotation、仅留旧 hash，设备仍持新密码重连会 deny，须回退旧密码重连（旧 hash 仍在）。
- 明文保护：新密码 TLS 下发一次即弃、永不落库，失败/超时也不回写明文。

## 八、限流（RotationRateLimiter）

| 维度 | 阈值 | 超限 |
|---|---|---|
| 单 `deviceSn` | 每小时最多 3 次请求 | 锁定 1 小时 |
| 单来源 IP | 每分钟最多 60 次 | 锁定 15 分钟 |

正常一轮（init→rotate）产生 2 次请求，占单 SN 每小时 3 次额度的 2 次、只剩 1 次重试余量：到第 3 次请求即到顶，再发第 4 次就锁 1 小时。别按「每轮 2 次、能试多轮」理解，撞锁会误判成自己没超。限流是防 deviceSecret 泄露探测，失败走退避等下周期，别加无脑重试放大器。

## 九、最小实现清单

| # | 项 | 必/选 |
|---|---|---|
| 1 | 订阅 `downlink/{deviceSn}/mgmt`，解析 `action=ROTATE_CREDENTIAL` | 必 |
| 2 | 生成 `clientNonce`（16-64 位小写 hex 随机）并调用 init 拿 `serverNonce` | 必 |
| 3 | 用 deviceSecret 按 §五 计算 HMAC 签名 | 必 |
| 4 | 调用 rotate 拿新 mqttPassword，写入 Flash 安全区 | 必 |
| 5 | 断开 MQTT 用新密码重连（命中新密码即云端关窗，无 confirm 调用） | 必 |
| 6 | 每次 HTTP 请求生成新 `X-Nonce` + 当前毫秒 `X-Timestamp` | 必 |
| 7 | 任一步失败走回退（继续用旧密码，等下一周期） | 必 |

## 十、常见问题排查

| 现象 | 排查方向 |
|---|---|
| 收不到 ROTATE_CREDENTIAL 指令 | ① 是否订阅 `downlink/{deviceSn}/mgmt` ② MQTT 认证是否用旧密码通过 ③ 凭据是否已到 90 天到期（未到期云端不会下发） |
| init / rotate 返回 401 | `X-Timestamp` 超 ±5 分钟窗、或 `X-Nonce` 复用、或签名错误 |
| 验签永不过（云端日志 HMAC verification failed） | 90% 是 key 用错：确认取 `sha256(deviceSecret)` 的 raw 32 字节，不是 hex 串 UTF-8 字节 |
| 429 限流 | 单 SN 每小时超 3 次请求、或单 IP 超频，退避等待 |
| 新密码连不上 MQTT | 确认已写 Flash 且用**新** mqttPassword；grace 内旧密码也应仍可用，若两者都不行查 Flash 写入是否损坏 |
| 关窗后仍被踢下线 | 确认关窗前已用新密码完成重连（关窗会固化新 hash、删旧 hash，旧密码随即失效） |

## 附：与激活接口的关系

凭证轮换的签名算法、防重放头、`clientNonce` 生成规则，与首次激活（规范 §5.1）**完全一致**，固件侧可复用同一套 HMAC 与 nonce 工具函数，只替换接口路径与 `signData` 拼接（激活与轮换的 signData 均为 `serverNonce + clientNonce + deviceSn`）。
